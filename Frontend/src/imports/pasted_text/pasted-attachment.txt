# MASTER PROMPT FIGMA MAKE

## UI/UX DESIGN SPECIFICATION

### RANCANG BANGUN WEB SERVICE PRESENSI DAN MANAJEMEN ASET LABORATORIUM KOMPUTER MENGGUNAKAN METODE AGILE

Create a complete, professional, desktop-first web UI/UX design and interactive prototype for a laboratory computer attendance and asset management system.

This is a WEB-ONLY product. Do not create Android, iOS, or mobile application screens.

The product consists of two separate web applications that use the same backend system:

1. Student Web
2. Admin / Laboratory Staff Web

The interface must look like a real production-ready academic laboratory management system, not a generic dashboard template.

The design must prioritize clarity, usability, consistency, accessibility, and realistic operational workflows.

---

# 1. PRODUCT CONTEXT

Product name:

RANCANG BANGUN WEB SERVICE PRESENSI DAN MANAJEMEN ASET LABORATORIUM KOMPUTER MENGGUNAKAN METODE AGILE

Product type:

Web-based laboratory attendance and asset management system.

Target users:

* Mahasiswa
* Admin / Laboran / Tata Usaha

Main product capabilities:

* Authentication
* User profile
* Face enrollment
* Face verification through browser camera
* Practical session management
* Attendance
* Check-in
* Check-out
* Asset management
* Asset allocation
* Asset return
* Asset history
* Maintenance
* Reporting
* Dashboard

Important business concept:

A student logs in first. The system already knows the student's identity.

The student then uses the browser camera for FACE VERIFICATION 1:1.

The system compares the face in front of the camera with the student's own registered face template.

Do NOT design face identification 1:N.

Do NOT design QR Code as the primary attendance method.

Do NOT design RFID.

Do NOT design hardware biometric scanners.

Do NOT design mobile applications.

The UI should communicate that face verification is a verification process, not a search for identity.

# 33. FACE VERIFICATION UX RULES

The face verification experience must be designed carefully because it is the key interaction of the student application.

The process must feel:

* trustworthy
* simple
* transparent
* private
* fast

Show the user:

1. Why camera access is needed.
2. That the process verifies the logged-in account.
3. That the camera is active.
4. Whether a face is detected.
5. Whether verification is in progress.
6. Whether verification succeeds or fails.

Do not show:

* raw embedding
* threshold number
* model internals
* technical similarity values

Do not imply absolute security.

Do not claim:

"100% secure"

"Cannot be cheated"

"Guaranteed anti-cheating"

Use language such as:

"Verifikasi wajah digunakan untuk membantu memastikan kesesuaian identitas pengguna yang sedang login."

# 47. IMPORTANT PRODUCT CONSTRAINTS

These constraints are mandatory:

* Web-only.
* Two web applications.
* Student and Admin are separate user experiences.
* REST API is the backend communication layer.
* No direct database access from frontend.
* Face verification uses 1:1 verification.
* Student must login before face verification.
* Face verification happens through browser camera.
* No QR Code as primary attendance.
* No 1:N face identification.
* No mobile application.
* No IoT.
* No RFID.
* No hardware scanner.
* No advanced AI dashboard.
* No training face recognition model from scratch.
* Use a pretrained face model conceptually.
* Do not expose biometric embedding or technical face model information in the UI.
* Do not claim biometric verification is 100% secure.
* The system is designed to reduce the potential for attendance abuse or proxy attendance.
